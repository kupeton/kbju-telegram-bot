## 1. Что будет работать в конце

После прохождения шагов ты сможешь открыть **собственного бота в Telegram** и:

- создавать продукт по данным с этикетки: название, бренд, магазин, КБЖУ на 100 г или 100 мл;
- сохранять продукты с метками **Пятёрочка**, **Магнит** или другим названием магазина;
- искать добавленные продукты по названию и бренду;
- отправлять **числовой штрихкод** и запрашивать товар в базе **Open Food Facts**;
- указывать, сколько граммов или миллилитров съел/выпил;
- автоматически получать калории, белки, жиры и углеводы порции;
- просматривать результаты за сегодняшний день и последние семь дней;
- задавать дневную цель по калориям;
- удалять последнюю запись в дневнике;
- закрыть бота, перезапустить программу и увидеть сохранённые данные снова.

**Пока бот не умеет:** сканировать штрихкод камерой, распознавать этикетку по фотографии, искать по названию во всём ассортименте Пятёрочки и Магнита, показывать Mini App. Внешний поиск реализован только по **цифровому штрихкоду**; обычный текстовый поиск проверяет **наш локальный каталог**.

## 2. Как устроен проект простыми словами

У нас есть три главные части:

```text
ТЫ В TELEGRAM
     |
     | сообщение /new, /today или /barcode
     v
TELEGRAM-БОТ (TypeScript, Node.js, grammY)
     |                          |
     | сохранить продукт        | поиск по штрихкоду
     v                          v
POSTGRESQL                  OPEN FOOD FACTS
(твои продукты,             (открытая внешняя база)
 дневник питания)
```

- **Telegram** — окно общения с ботом.
- **Node.js** — программа, которая запускает наш TypeScript-код.
- **npm** — устанавливает нужные библиотеки.
- **Docker Desktop** — запускает PostgreSQL в отдельном контейнере, чтобы не настраивать сервер базы вручную.
- **PostgreSQL** — хранит продукты и записи питания.
- **Prisma** — создаёт таблицы и связывает TypeScript-код с базой.
- **Open Food Facts** — открытый источник информации о товарах по штрихкоду. Данные могут быть неполными или неточными.

**Первый запуск выполняем на твоём компьютере.** Сервер в интернете или домен пока не нужны: бот получает сообщения через Telegram **long polling**. Это значит, что он отвечает, пока компьютер включён, Docker работает и процесс `npm run dev` запущен.

## 4. Установка программ

### 4.1. Установи Node.js

1. Открой официальный сайт: <https://nodejs.org/en/download>.
2. Выбери стабильный релиз **Node.js 24** либо версию **22.18 или новее**. Слишком старые версии 18, 20 и ранние 22 не подходят для текущего `package.json`.
3. Установи Node.js обычным установщиком для своей ОС.
4. Закрой и вновь открой терминал после установки, чтобы система увидела новые команды.

Как открыть терминал:

- **Windows:** нажми **Win**, введи `PowerShell` или `cmd` и открой терминал. Можно также выбрать **Terminal → New Terminal** в Visual Studio Code.
- **macOS:** открой приложение **Terminal** через Spotlight (`⌘ + пробел`).
- **Linux:** открой стандартный Terminal, часто `Ctrl + Alt + T`.

В терминале введи **по одной команде**:

```bash
node -v
npm -v
```

Ожидаемый результат: терминал выводит две версии, например `v24.x.x` и `11.x.x` (точные цифры отличаются). Важно, чтобы первая команда показывала подходящую версию Node.js, а не сообщение «команда не найдена».

Если Node.js уже установлен, но версия старая, обнови его **до запуска проекта**.

### 4.2. Установи Docker

- **Windows:** <https://docs.docker.com/desktop/setup/install/windows-install/>.
- **macOS:** <https://docs.docker.com/desktop/setup/install/mac-install/>.
- **Linux:** <https://docs.docker.com/engine/install/> и плагин Compose.

На Windows Docker Desktop часто использует **WSL 2**. Если установщик попросит включить WSL/виртуализацию или перезагрузить компьютер, выполни инструкцию установщика. Важно не просто установить Docker, но и **запустить приложение Docker Desktop**, дождаться, пока движок станет доступен.

Проверь в терминале:

```bash
docker --version
docker compose version
```

В обеих командах должны появиться номера версий. Команда с пробелом `docker compose` — правильный современный вариант. **Не путай** с устаревшим `docker-compose`.

Проверь, что движок Docker запущен:

```bash
docker info
```

Если вывод большой — это нормально. Если написано `Cannot connect to the Docker daemon`, Docker Desktop ещё не запущен или не готов.

### 4.3. Установи Visual Studio Code (необязательно, но удобно)

Скачать: <https://code.visualstudio.com/>.

Он нужен для просмотра кода, редактирования `.env` и открытия терминала прямо в папке проекта. Можно использовать другой редактор, но **не Word**: конфигурационные файлы должны оставаться обычным текстом.

## 6. Создание бота через BotFather

### 6.1. Найди официального BotFather

1. Открой Telegram.
2. Перейди по ссылке <https://t.me/BotFather>.
3. Нажми **Start** / «Запустить».
4. Отправь команду:

```text
/newbot
```

### 6.2. Придумай название и username

BotFather задаст два вопроса:

1. **Name** — отображаемое имя. Например: `Мой КБЖУ`.
2. **Username** — уникальный адрес бота, например: `my_personal_kbju_bot`. Он должен быть свободным и заканчиваться на `bot` (без пробелов, латинскими буквами/цифрами/допустимыми символами).

Если название занято, BotFather попросит другое. Это нормально — придумай уникальный вариант.

### 6.3. Скопируй токен

После создания BotFather пришлёт длинную строку вида:

```text
<BOT_TOKEN_FROM_BOTFATHER>
```

**Это пример, а не настоящий токен!** Настоящий токен будет отличаться.

Токен — секретный пароль доступа к управлению ботом. Держи его **только у себя**. Никому не отправляй токен в Telegram, ChatGPT, GitHub, скриншотах или публичных файлах. Вставлять его нужно только в `.env` на своём компьютере.

Если случайно раскрыл токен, через BotFather можно **отозвать его командой `/revoke`**, выбрать бота и заменить старый токен новым в `.env`.

## 7. Создание и заполнение `.env`

`.env` — специальный файл с настройками проекта. **Он должен называться ровно `.env`**, без имени, без расширения `.txt`.

### 7.1. Создай файл из примера

В терминале **в папке проекта** выполни команду для своей системы.

**Windows PowerShell:**

```powershell
Copy-Item .env.example .env
```

**Windows CMD:**

```cmd
copy .env.example .env
```

**macOS/Linux:**

```bash
cp .env.example .env
```

Можно скопировать файл и в Проводнике, но Windows иногда скрывает расширения, и легко случайно создать `.env.txt`. Надёжнее выполнить команду.

### 7.2. Открой `.env` в текстовом редакторе

В дереве файлов VS Code нажми `.env`. Если файла не видно, обнови дерево и убедись, что команда копирования выполнилась без ошибки.

Содержимое должно быть примерно таким:

```dotenv
BOT_TOKEN=INSERT_BOT_TOKEN_HERE
DATABASE_URL=postgresql://kbju:local_dev_only_change_me@localhost:5432/kbju?schema=public
OFF_USER_AGENT=MyPersonalKBJUBot/0.1 (your-email@example.com)
DEFAULT_TIMEZONE=Europe/Moscow
```

### 7.3. Измени `BOT_TOKEN`

Вместо `INSERT_BOT_TOKEN_HERE` вставь свой **реальный токен BotFather**, без угловых скобок и кавычек:

```dotenv
BOT_TOKEN=ТВОЙ_РЕАЛЬНЫЙ_ТОКЕН_ОТ_BOTFATHER
```

Строка выше лишь показывает место вставки. В финальном `.env` не должно остаться слов `ТВОЙ_РЕАЛЬНЫЙ_ТОКЕН_ОТ_BOTFATHER`.

### 7.4. Проверь `DATABASE_URL`

Для первого запуска **ничего менять не нужно**, если используешь Docker-конфигурацию из архива:

```dotenv
DATABASE_URL=postgresql://kbju:local_dev_only_change_me@localhost:5432/kbju?schema=public
```

Разбор строки:

- `postgresql://` — тип базы;
- `kbju` до двоеточия — имя пользователя PostgreSQL;
- `local_dev_only_change_me` — **учебный пароль**;
- `localhost` — база на твоём компьютере;
- `5432` — порт;
- `kbju` после порта — имя базы.

Логин, пароль, название базы и порт должны соответствовать `docker-compose.yml`. Учебный пароль предназначен **только для локального запуска**; не открывай PostgreSQL с ним в интернет.

### 7.5. Обязательно измени `OFF_USER_AGENT`

Это поле нужно для запросов к Open Food Facts. Используй **свой действительный контактный email**, например в формате:

```dotenv
OFF_USER_AGENT=MyKBJUBot/0.1 (me@my-domain.ru)
```

Здесь `me@my-domain.ru` — **пример формата**, не оставляй его как есть. Замени на адрес, которым реально владеешь. В этом проекте код откажется делать внешний поиск, если там останется `example.com`.

Open Food Facts просит указывать идентификатор вида `НазваниеПриложения/Версия (КонтактныйEmail)`. Этот адрес используется для идентификации клиента; **он не является логином или паролем** к почте. Не записывай в `.env` пароль от почты.

### 7.6. При необходимости выбери часовой пояс

```dotenv
DEFAULT_TIMEZONE=Europe/Moscow
```

Это значение применяется **при создании нового пользователя**. Примеры:

- `Europe/Moscow` — Москва;
- `Europe/Kaliningrad` — Калининград;
- `Asia/Yekaterinburg` — Екатеринбург;
- `Asia/Novosibirsk` — Новосибирск;
- `Asia/Vladivostok` — Владивосток;
- `America/Chicago` — Чикаго.

Позже можно сменить часовой пояс прямо в Telegram: `/timezone Europe/Moscow`. Изменение часового пояса влияет на **будущие** записи и определение текущего дня, но не переносит уже сохранённые записи в другие дни.

### 7.7. Сохрани `.env`

Нажми **Ctrl + S** (Windows/Linux) или **⌘ + S** (macOS).

**Контрольная проверка:**

- файл называется `.env`, а не `.env.txt`;
- токен заменён на настоящий;
- в `OFF_USER_AGENT` стоит твой контактный email;
- `DATABASE_URL` оставлен без изменений, если используешь прилагаемый Docker Compose;
- нет дополнительных кавычек, пропущенных `=` или случайных пробелов внутри значений.

## 8. Запуск PostgreSQL через Docker

### 8.1. Зачем он нужен

Бот должен помнить продукты и дневник между запусками. Поэтому ему нужна база PostgreSQL. Docker запускает её как отдельную программу-контейнер.

### 8.2. Запусти Docker Desktop

Если у тебя Windows/macOS — сначала вручную открой Docker Desktop. Убедись, что его движок работает.

### 8.3. Запусти базу

**В терминале из папки проекта** выполни:

```bash
docker compose up -d
```

Первая команда может загрузить образ `postgres:16-alpine`. После завершения Docker оставит контейнер базы работающим в фоне (`-d` означает *detached*).

> Эта команда запускает **только PostgreSQL**, а **не самого Telegram-бота**. Бот мы отдельно запустим через npm.

### 8.4. Проверь состояние контейнера

```bash
docker compose ps
```

Ожидаешь сервис с именем `postgres` и состоянием вроде `running` / `Up`, после начала работы — `healthy`.

Можно проверить готовность самой базы:

```bash
docker compose exec postgres pg_isready -U kbju -d kbju
```

Если получишь `accepting connections` — база готова. Иногда первая проверка проходит слишком рано: просто повтори её, когда контейнер закончит запуск.

### 8.5. Если порт `5432` занят

Признак: Docker сообщает что-то вроде `port is already allocated` или `Bind for 0.0.0.0:5432 failed`.

В таком случае:

1. Открой `docker-compose.yml`.
2. Найди строку:

   ```yaml
   ports:
     - "5432:5432"
   ```

3. Измени **только число слева**:

   ```yaml
   ports:
     - "5433:5432"
   ```

4. В `.env` измени порт подключения:

   ```dotenv
   DATABASE_URL=postgresql://kbju:local_dev_only_change_me@localhost:5433/kbju?schema=public
   ```

5. Сохрани файлы и снова выполни `docker compose up -d`.

Важно: в `5433:5432` число `5433` — порт компьютера, а `5432` — порт внутри контейнера. В `DATABASE_URL` нужен именно **5433**.

### 8.6. Если Docker установить нельзя: альтернативный PostgreSQL

Этот вариант для тех, у кого **уже установлен PostgreSQL 16+** или есть опыт с `psql`.

Нужно создать пользователя `kbju`, базу `kbju` и настроить строку `DATABASE_URL` под реальные логин/пароль/хост/порт. Например, администратор PostgreSQL может создать их SQL-командами:

```sql
CREATE ROLE kbju WITH LOGIN PASSWORD 'СВОЙ_НАДЁЖНЫЙ_ПАРОЛЬ' CREATEDB;
CREATE DATABASE kbju OWNER kbju;
```

`CREATEDB` полезен для разработки, потому что Prisma `migrate dev` может создавать **shadow database**. Пароль с символами `@`, `:`, `/`, `?`, `#` и другими специальными знаками надо корректно кодировать в URL. После этого **не запускай `docker compose up -d`**, а выполняй npm-команды из разделов ниже.

Для первого проекта Docker обычно проще.

### 10.1. Проверь, что Docker работает

## 12. Проверка полного сценария на продукте

Проверим весь цикл: **создали продукт → внесли порцию → посмотрели дневник → удалили порцию**.

> Ниже КБЖУ **условное, для проверки**. Не считай эти цифры автоматически верными для реального «Простоквашино»: значения на упаковке конкретного продукта могут отличаться.

### Шаг 1. Начни добавление

В Telegram отправь:

```text
/new
```

Бот спросит название продукта.

### Шаг 2. Ответь на восемь вопросов по порядку

| Вопрос бота | Что отправить |
|---|---|
| Название продукта | `Творог 5%` |
| Бренд | `Простоквашино` |
| Где куплен? | `Пятёрочка` |
| КБЖУ на 100 г или 100 мл? | `г` |
| Калории на 100 г | `121` |
| Белки на 100 г | `17` |
| Жиры на 100 г | `5` |
| Углеводы на 100 г | `2` |

**Отправляй ответы по одному, каждый раз дожидаясь следующего вопроса.** Если бренда нет или магазин не важен, вместо названия отправь один знак `-`. Если нужно указать два магазина: `Пятёрочка, Магнит`.

После последнего ответа появится сообщение `Продукт сохранён в твоём личном каталоге` и кнопка **«➕ Съел — указать вес»**.

### Шаг 3. Добавь порцию в дневник

1. Нажми **«➕ Съел — указать вес»**.
2. Бот спросит количество в граммах.
3. Отправь:

   ```text
   150
   ```

4. Бот посчитает порцию по формуле:

   ```text
   Значение на порцию = значение на 100 г × 150 / 100
   ```

Ожидаемый результат для **наших тестовых чисел**:

| Показатель | На 100 г | На 150 г |
|---|---:|---:|
| Калории | 121 ккал | **181,5 ккал** |
| Белки | 17 г | **25,5 г** |
| Жиры | 5 г | **7,5 г** |
| Углеводы | 2 г | **3 г** |

### Шаг 4. Посмотри сегодняшний дневник

```text
/today
```

Ты должен увидеть сегодняшнюю дату (в выбранном часовом поясе), общее КБЖУ и строку с добавленным творогом.

### Шаг 5. Проверь поиск по названию

```text
/search творог
```

Бот найдёт **личную карточку**, которую ты только что создал. Можно нажать кнопку рядом с найденным продуктом и добавить ещё одну порцию.

### Шаг 6. Проверь поиск по магазину

```text
/store пятерочка
```

Должен отобразиться продукт с меткой «Пятёрочка». Это **не** проверка реального наличия творога в магазинах: это информация, введённая тобой в карточку.

### Шаг 7. Установи дневную цель

```text
/goal 2200
```

Теперь `/today` дополнительно покажет дневную цель и оставшееся/превышенное количество ккал. Число `2200` здесь — **пример пользовательского ввода**, не персональная рекомендация по питанию.

### Шаг 8. Проверь историю

```text
/history
```

Бот покажет КБЖУ каждого из последних **7 дней**, включая дни без записей.

### Шаг 9. Удали тестовую запись (если хочешь)

```text
/undo
```

Бот удалит **последнюю по времени запись в дневнике**. Он **не удаляет сам продукт** из каталога. Если ты добавил несколько порций, `/undo` нужно повторить для каждой в обратном порядке.

## 13. Все команды бота с примерами

| Команда | Пример | Результат |
|---|---|---|
| `/start` | `/start` | Открыть меню |
| `/help` | `/help` | Показать справку |
| `/new` | `/new` | Начать добавление продукта по этикетке |
| `/search` | `/search творог` | Искать по имени или бренду в **личном + общем локальном** каталоге |
| `/store` | `/store магнит` | Показать локальные продукты с меткой «Магнит» |
| `/barcode` | `/barcode 3017620422003` | Попробовать найти товар по цифрам штрихкода через Open Food Facts |
| `/today` | `/today` | Показать КБЖУ и порции за текущий день |
| `/history` | `/history` | Показать суммарные значения за последние 7 дней |
| `/goal` | `/goal 2200` | Установить цель от 100 до 10 000 ккал |
| `/timezone` | `/timezone Europe/Moscow` | Изменить часовой пояс будущих записей |
| `/undo` | `/undo` | Удалить последнюю запись из дневника |
| `/cancel` | `/cancel` | Прервать текущий пошаговый ввод |

Ещё две удобные возможности:

- Можно просто отправить `творог` — бот воспримет текст как поиск по названию в локальном каталоге.
- Можно отправить `3017620422003` — 8–14 цифр без других символов будут интерпретироваться как штрихкод.

**При добавлении продукта через `/new`** все следующие обычные текстовые сообщения считаются **ответами на вопросы**, а не поиском. Если запутался, отправь `/cancel` и начни заново.

Ввод порции должен быть **числом больше нуля и не больше 10 000**, например `150` или `150,5`. Для продукта на 100 г количество будет в граммах; для продукта на 100 мл — в миллилитрах.

Если ты не успел закончить пошаговый диалог, **через 20 минут бездействия** он истечёт. После перезапуска программы незаконченный диалог тоже теряется: его состояние пока хранится в памяти Node.js, но **сохранённые продукты и завершённые записи не пропадают**.

## 14. Как использовать товары из Пятёрочки и Магнита

### Вариант A. Добавить товар по этикетке (самый надёжный способ)

Представим, ты купил йогурт или творог в магазине.

1. Найди на упаковке название, бренд, вес/объём.
2. Найди пищевую ценность **на 100 г** или **на 100 мл**.
3. Открой бота → `/new`.
4. Введи данные с упаковки.
5. На вопрос «Где куплен?» укажи `Магнит` или `Пятёрочка`.
6. Сохрани товар.
7. Нажми «➕ Съел — указать вес» и введи съеденное количество.

**Если на упаковке указано КБЖУ только на порцию, а не на 100 г/мл**, сначала пересчитай по правилу:

```text
На 100 г = значение на порцию × 100 / вес порции в граммах
```

Например, если 80 г продукта содержит 96 ккал, то на 100 г будет `96 × 100 / 80 = 120 ккал`. То же отдельно для Б, Ж и У. Не смешивай граммы с миллилитрами без информации о плотности продукта.

### Вариант B. Найти товар по штрихкоду

1. Посмотри цифры под полосками штрихкода.
2. Отправь их боту, например:

   ```text
   /barcode 3017620422003
   ```

3. Бот сначала проверит **локальную базу**, а при отсутствии товара обратится к Open Food Facts.
4. Если нашёл полное КБЖУ, покажет продукт и кнопку добавления порции.
5. **Проверь цифры на своей упаковке**, поскольку данные Open Food Facts заполняются участниками сообщества.

Пример штрихкода выше нужен только для проверки механизма; он не означает, что такой товар продаётся в Пятёрочке или Магните.

**Важные ограничения:**

- камера телефона **пока не считывает штрихкод автоматически** — необходимо набрать/скопировать цифры;
- поиск по штрихкоду может не найти некоторые российские продукты;
- если в Open Food Facts не хватает хотя бы одного из четырёх показателей КБЖУ, бот **не подставляет нули**, а предлагает ручное добавление;
- импортированные карточки Open Food Facts не получают автоматически метку Пятёрочки или Магнита;
- метка магазина — не свидетельство актуальной цены, ассортимента или наличия товара.

### Вариант C. Использовать продукт повторно

Товар уже добавлен однажды? Не нужно заново вводить всё КБЖУ:

```text
/search йогурт
```

Выбери нужную карточку → нажми кнопку **«➕»** → введи граммы/миллилитры. Так постепенно появится твой персональный каталог покупок.

## 17. Типичные ошибки и решения

Ниже — самые распространённые ситуации. Сначала внимательно прочитай **полный текст ошибки**, затем выбери подходящий пункт.

### 17.1. `node` или `npm`: команда не найдена

**Причина:** Node.js не установлен или терминал не обновил переменную PATH.

**Решение:** установи Node.js с официального сайта, закрой и заново открой терминал, проверь `node -v` и `npm -v`. Используй Node.js **22.18+** или 24.

### 17.2. PowerShell пишет: `npm.ps1 cannot be loaded because running scripts is disabled`

Это ограничение политики PowerShell, а не ошибка нашего проекта.

Простые безопасные варианты: открыть **Command Prompt (CMD)** в Windows или выполнять команды с `.cmd`, например:

```powershell
npm.cmd install
npm.cmd run dev
```

Не нужно ослаблять глобальные настройки безопасности только ради запуска бота.

### 17.3. `ENOENT` / `Could not read package.json`

Ты запускаешь npm **не из той папки**. Открой папку `kbju-telegram-bot`, где расположен `package.json`, и повтори команду.

### 17.4. `docker: command not found` или `docker is not recognized`

Docker не установлен, не добавлен в PATH или терминал не перезапущен после установки. Установи Docker и заново открой терминал.

### 17.5. `Cannot connect to the Docker daemon`

Запусти Docker Desktop, проверь его статус и попробуй `docker info`. На Linux потребуется запущенная служба Docker и разрешение на доступ к ней.

### 17.6. `port is already allocated` для `5432`

Другой PostgreSQL или контейнер уже использует порт. Используй `5433:5432` в `docker-compose.yml` **и** `localhost:5433` в `.env`, как показано в разделе 8.5.

### 17.7. `Environment variable not found: DATABASE_URL`

Отсутствует или не загружается `.env`. Проверь, что:

- ты в папке проекта;
- есть файл **`.env`**, а не `.env.txt`;
- в нём присутствует `DATABASE_URL=...`;
- строка не закомментирована символом `#`.

### 17.8. `Укажи BOT_TOKEN в .env`

В `.env` оставлена строка `INSERT_BOT_TOKEN_HERE` или не указан `BOT_TOKEN`. Вставь реальный токен от BotFather. Не публикуй его.

### 17.9. Ошибка Telegram `401 Unauthorized`

Обычно токен неверный, опечатан, отозван или в нём есть лишние символы. Скопируй актуальный токен у BotFather, обнови `.env` и перезапусти `npm run dev`.

### 17.10. Ошибка Telegram `409 Conflict`

Часто означает, что **другой процесс уже получает сообщения от того же бота**. Останови лишние копии `npm run dev` и другую программу, использующую тот же токен. Для текущего проекта нужен один активный polling-процесс на бота.

### 17.11. `P1001` или `Can't reach database server`

Приложение не может подключиться к PostgreSQL.

Проверь последовательно:

```bash
docker compose ps
docker compose exec postgres pg_isready -U kbju -d kbju
```

Затем сопоставь порт в `docker-compose.yml` с портом в `DATABASE_URL`. Убедись, что контейнер запущен.

### 17.12. `P1000` / `Authentication failed against database server`

Неправильный логин или пароль PostgreSQL. Сравни `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` в `docker-compose.yml` со строкой `DATABASE_URL`.

**Важно:** если база уже создана внутри постоянного Docker-тома, изменение `POSTGRES_PASSWORD` в YAML **не обязательно поменяет пароль существующего пользователя в БД**. Не удаляй том наугад: там твой дневник. При необходимости исправь пароль через PostgreSQL или попроси помощи с диагностикой.

### 17.13. Prisma просит `reset database`

**Не соглашайся автоматически.** `reset` может удалить все продукты и записи. Остановись, сохрани вывод ошибки без секретов и разбери состояние миграций. Особенно важно, если базой уже пользуешься.

### 17.14. `Cannot find module ... generated/prisma/client.ts`

Скорее всего, не выполнена генерация Prisma Client:

```bash
npm run db:generate
```

Если не помогает, проверь ошибки предыдущего `npm install` и `npm run db:migrate`.

### 17.15. Telegram-бот не отвечает, но ошибок не видно

Проверь:

1. Открыта ли **личная переписка** с ботом? Код **игнорирует групповые чаты**.
2. Запущен ли `npm run dev`?
3. Правильного ли бота ты открыл (username из BotFather)?
4. Есть ли интернет у компьютера?
5. Нет ли второй копии процесса с тем же токеном?
6. Отправляешь ли ты `/start` после запуска?

### 17.16. Бот сообщает: «Время ввода истекло»

Ввод продукта или порции живёт **20 минут**. Отправь `/new` заново либо найди товар через `/search` и снова нажми кнопку добавления.

### 17.17. `/search молоко` не находит обычное молоко из супермаркета

Это ожидаемо, если такого товара ещё нет **в нашем локальном каталоге**. `/search` не ищет по всему интернету. Добавь товар через `/new` или проверь его штрихкод через `/barcode`.

### 17.18. `/barcode` пишет «Товар не найден или в базе нет полного КБЖУ»

В Open Food Facts может не быть этой карточки или у неё отсутствуют некоторые показатели. Введи данные с этикетки вручную через `/new`. Это не означает, что продукта нет в магазине.

### 17.19. `/barcode` пишет «Настрой OFF_USER_AGENT»

В `.env` остался учебный адрес с `example.com` или отсутствует значение. Поставь собственный идентификатор и контактный email, затем перезапусти бот.

### 17.20. В дневнике неправильная дата

Часовой пояс настраивается отдельно для пользователя. Выполни, например:

```text
/timezone Europe/Moscow
```

Далее `/today` будет использовать указанный пояс. **Старые записи автоматически не переносятся между датами**.

### 17.21. Docker-контейнер удалён, а данные пропали

Сами контейнеры могут пересоздаваться, но **данные лежат в именованном Docker-томе `postgres_data`**. Обычно команды `docker compose stop` и `docker compose down` том не удаляют. Однако `docker compose down -v`, ручное удаление томов и команды очистки Docker могут **безвозвратно удалить данные**.

### 17.22. `npm install` завершается ошибкой сети

Проверь соединение с интернетом, доступ к npm registry, VPN/прокси и настройки сети. Повтори установку. Не скачивай библиотеки с подозрительных сайтов и не отключай системную защиту ради npm.

### 17.23. Нужна помощь с сообщением об ошибке

Чтобы разобраться, обычно достаточно прислать:

- какая у тебя ОС (Windows/macOS/Linux);
- какую **команду** ты выполнял;
- **текст ошибки**, но без секретов;
- результаты `node -v`, `npm -v` и `docker compose ps` (если Docker установлен).

**Перед отправкой убери:** Telegram-токен, email, пароли, содержимое `.env`, чувствительные URL подключения и личные данные.

## 18. Сохранность данных, безопасность и резервные копии

### 18.1. Где живут данные

- Личный каталог и съеденные порции хранятся **в PostgreSQL**.
- PostgreSQL внутри Docker использует именованный том `postgres_data`.
- Сам бот получает доступ к базе через `DATABASE_URL`.
- Для каждого пользователя есть отдельный Telegram ID. Добавленные вручную продукты привязаны к владельцу. Общие карточки Open Food Facts доступны другим пользователям этого экземпляра бота.

### 18.2. Что категорически не делать

- **Не публикуй `.env`** и токен BotFather.
- **Не добавляй `.env` в GitHub** или ZIP-архив для друзей. В `.gitignore` этого проекта `.env` уже указан, но всё равно проверяй, что отправляешь.
- **Не запускай** `docker compose down -v` для повседневной остановки — ключ `-v` удаляет тома, включая данные PostgreSQL.
- **Не запускай** `npx prisma migrate reset`, если хочешь сохранить дневник.
- **Не открывай** порт PostgreSQL из этого учебного проекта напрямую в интернет.
- **Не используй** учебный пароль базы из шаблона на публичном сервере.

### 18.3. Создай резервную копию

Когда бот заработает и в нём появятся настоящие данные, полезно сохранять дампы базы перед серьёзными изменениями.

Для **macOS/Linux или Windows CMD** (не старого Windows PowerShell с текстовым перенаправлением) можно выполнить из папки проекта:

```bash
docker compose exec -T postgres pg_dump -U kbju -d kbju > kbju-backup.sql
```

Это создаст SQL-файл с содержимым базы в текущей папке. Убедись, что файл не пустой, и сохрани отдельную копию в безопасном месте. **SQL-дамп содержит твой дневник питания**: не публикуй его в открытых репозиториях. На старом Windows PowerShell редирект `>` способен изменить кодировку; для этой команды лучше открыть **CMD**.

Восстановление зависит от состояния текущей базы, поэтому **не запускай случайные команды `psql` / `restore`, если в базе уже есть важные данные**. Сначала сохрани ещё одну резервную копию и определи порядок восстановления.

### 18.4. Как беречь данные и токен

- Создай для GitHub отдельный репозиторий **без `.env`**.
- Храни свой Telegram-токен в локальном `.env` или защищённом менеджере секретов.
- Если делаешь проект публичным, настрой новые пароли, ограничения доступа и HTTPS для будущего сервера.
- Telegram-бот — **не секретный чат с end-to-end шифрованием**. Не отправляй ему пароли, паспортные данные и другое лишнее содержимое.
- Пользовательские показатели и калорийные цели — персональная информация; не делись её выгрузками без необходимости.

## 19. Структура проекта и принцип работы кода

### 19.1. Файлы проекта

```text
kbju-telegram-bot/
│
├── package.json            зависимости и команды npm
├── .env.example            шаблон переменных окружения
├── .env                    твои локальные секреты (создаёшь сам)
├── docker-compose.yml      локальный PostgreSQL в Docker
├── prisma.config.ts        настройка Prisma и DATABASE_URL
├── tsconfig.json           настройки TypeScript
├── README.md               краткая инструкция
├── README_DETAILED.md      эта подробная инструкция
│
├── prisma/
│   ├── schema.prisma       описание таблиц
│   └── migrations/         появится после npm run db:migrate
│
├── src/
│   ├── bot.ts              команды, кнопки, пошаговый ввод
│   ├── db.ts               подключение к PostgreSQL
│   ├── nutrition.ts        формулы КБЖУ, проверка чисел и дат
│   └── off.ts              запрос продукта по штрихкоду
│
├── tests/
│   ├── nutrition.test.ts   тесты расчёта КБЖУ
│   └── off.test.ts         тест внешнего API на макете ответа
│
├── generated/prisma/       появится после db:generate
└── node_modules/           появится после npm install
```

### 19.2. Таблицы

**`User`** — `telegramId`, часовой пояс, калорийная цель и время создания пользователя.

**`Product`** — название, бренд, список магазинов, штрихкод (если найден через Open Food Facts), единица `G100` или `ML100`, четыре значения КБЖУ и источник `MANUAL` / `OPEN_FOOD_FACTS`.

**`FoodEntry`** — какой продукт добавлен, каким пользователем, какой день, сколько съедено, рассчитанные КБЖУ и время записи.

Особенность: в `FoodEntry` сохраняются **отдельные значения КБЖУ порции**, а не только ссылка на продукт. Это нужно, чтобы история не изменилась при возможных будущих корректировках карточки.

### 19.3. Где искать нужную логику

| Нужно изменить | Где искать |

| Параметры подключения к БД | `src/db.ts`, `.env`, `prisma.config.ts` |
| Тесты | `tests/` |

**Совет:** сначала убедись, что исходный проект работает. Потом меняй по одному файлу/функции, запускай `npm test` и `npm run check`, проверяй бота в Telegram. Так проще обнаружить ошибки.

## 20. Чего пока нет и что разработаем дальше

**Готово в версии v0.1:** локальный Telegram-бот, база данных, текстовый поиск в локальном каталоге, учёт порций, дневник, поиск по цифровому штрихкоду.

**План развития:**

1. **Telegram Mini App на React + Vite**: полноценный экран со сводкой КБЖУ, прогресс-барами, каталогом и кнопкой «Добавить».
2. **Поиск по более широкой базе продуктов**: не только локальные названия и цифровые штрихкоды; отдельное внимание — товарам из российских сетей, но без выдуманного ассортимента или наличия.
3. **Сканер штрихкодов камерой** в Mini App.
4. **Добавление по фотографии этикетки** с проверкой распознанных значений человеком.
5. **Редактирование и удаление любой записи**, пользовательские рецепты, сохранённые блюда, цели белков/жиров/углеводов и статистика по периодам.
6. **Развёртывание 24/7** на сервере с безопасной конфигурацией и резервными копиями.

Чтобы Mini App безопасно распознавал пользователя Telegram, серверная часть должна будет **проверять Telegram `initData`**; нельзя просто доверять данным, пришедшим из интерфейса.
